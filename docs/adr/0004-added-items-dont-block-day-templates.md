# Automatically added items don't block Day Templates, and a Day Template replaces the ones it duplicates

An Anchor, Flex, or Draft record gains an optional `source` (`"daily"` or `"icloud"`; absent means you added, promoted, or inserted it yourself). The "Session has items" check behind the weekday Day Template offer and both applies (weekday and manual) ignores any record with a `source`; only your own items, and To-dos, count as making the Session non-blank. Placing, resizing, or Dropping an added item doesn't change that.

Before seeding its entries, a Day Template apply removes every `source: "daily"` Flex that an entry duplicates — by the same Activity Template id, or by name ignoring letter case, whether the duplicating entry is an Anchor or a Flex — even one already placed or given a different duration. Only the duplicates go; other Daily Activities stay. Removal and seeding happen inside one mutation, so a single Undo restores exactly what was removed.

**Why:** Daily Activities and iCloud import both write into the Session before you've made a choice about anything, which used to make "blank Session" false and hide the Day Template offer on most nights — the whole point of Daily Activities. A Day Template should still be free to state its own version of a Daily Activity (a different duration, a fixed start, an attached Checklist) without producing two copies of the same activity.

**Considered:** tracking "added" items in a separate list instead of a record field — rejected, since Anchor/Flex/Draft records already flow through one shared shape in `tomorrow/session.py`, and a parallel list would need to stay in sync with every mutation (Place, Change Duration, Drop) that already touches the record in place. Matching Day Template duplicates by name only, with no Activity Template reference — rejected, since two Activity Templates with the same name would misfire, and the Day Template UI already lets an entry reference an Activity Template id directly.
